# 記録の仕組みをセットアップする

`docs/decisions/index.md` と、決定事項の索引を毎セッション読み込ませるための `AGENTS.md` 内の記述を用意します。
仕組みの導入を依頼された場合、または決定記録を作成する前の確認でいずれかが不足していた場合に実施します。

## 用意するもの

| 前提 | 不足している場合に実施すること |
|---|---|
| `docs/decisions/index.md` | 下記の「索引の雛形」をもとに作成する。`<プロジェクト名>` は、`AGENTS.md` や README の見出しにあるプロジェクト名に置き換える。不明な場合はユーザーに確認する |
| `AGENTS.md` またはハーネスが読み込む指示ファイル内にある `@docs/decisions/index.md` の記述（位置や見出しは不問。コードブロックやバッククォートで囲まれていないこと） | 下記の「指示ファイルに追加するセクション原文」を一字一句そのまま `AGENTS.md` の末尾に追加する。コードブロックの囲みは含めない。`AGENTS.md` が存在しない場合は、先頭にプロジェクト名の見出しと概要を記述して新規作成する |

### 索引の雛形

```markdown
# <プロジェクト名> の決定事項
```

### 指示ファイルに追加するセクション原文

```markdown
## プロジェクトの決定事項

`docs/decisions/index.md` の内容がコンテキストに読み込まれていない場合は、作業開始時に直接参照する。

- ファイルや機能を変更する前に、その変更に関係する決定記録が索引にないか照合する。関係する項目があれば、全文を参照したうえで作業を進める
- これから行う変更が、accepted の決定、proposed の決定にある決着までの取り決め、rejected の案のいずれかに当たる場合は、着手する前にユーザーへ確認する
- ユーザーがその変更を承認した場合や、proposed の論点が会話の中で決着した場合は、作業完了時に決定記録の更新を提案する
- 決定記録の作成や更新は、ユーザーから指示されたときのみ行う。直接手作業で編集せず、decision-record スキルを使用する

@docs/decisions/index.md
```

## 遵守事項

- 既存の内容は書き換えず、`AGENTS.md` の末尾に追記するのみとします
- 導入を依頼された場合はもちろん、決定記録を作成する過程で不足を発見した場合も、事前の許可取りを待たずにセットアップを進めて構いません。追加したファイルや記述は作業完了時にユーザーへ報告します
- セクション末尾の `@docs/decisions/index.md` の行は、コードブロックやバッククォートで囲まずプレーンテキストとして記述します。この1行により毎セッション索引が自動で読み込まれます。囲んでしまうと自動読み込みが機能しません
- 利用しているハーネスが `AGENTS.md` ではなく独自の指示ファイルを参照する場合は、作業前にユーザーへ伝えます。その指示ファイルから `AGENTS.md` を読み込ませる構成にすれば問題ありません
- コミットは勝手に実行しません

## 動作確認

配置完了後、新しいセッションで「決定事項の索引には何が記載されている？」と質問し、索引の内容が正常に返ってくるか確認するようユーザーへ依頼します。
