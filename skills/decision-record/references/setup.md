# 記録の仕組みを用意する

`docs/decisions/index.md` と、索引を毎セッション読み込ませる `AGENTS.md` の「プロジェクトの決定」の節を用意する。
記録の仕組みの導入を頼まれたとき、または決定を書く前の確認でどちらかが欠けていたときに行う。

## 用意するもの

| 前提 | 無いときに行うこと |
|---|---|
| `docs/decisions/index.md` | 下の「索引の雛形」で作る。`<プロジェクト名>` は、`AGENTS.md` やREADMEの見出しにあるプロジェクト名に置き換える。分からなければユーザーに聞く |
| `AGENTS.md` か、ハーネスが読む指示ファイルのどこかにある `@docs/decisions/index.md` の行。位置や見出しは問わず、コードブロックやバッククォートで囲まれていないこと | 下の「節の原文」を、一字一句そのまま `AGENTS.md` の末尾に足す。コードブロックの囲みは含めない。`AGENTS.md` が無ければ、先頭にプロジェクト名の見出しと説明を1行書いて作る |

### 索引の雛形

```markdown
# <プロジェクト名> の決定
```

### 節の原文

```markdown
## プロジェクトの決定

`docs/decisions/index.md` の内容がコンテキストに無ければ、作業の最初に読む。

- ファイルや機能を変更する前に、その変更に関係する決定が索引にないか照らし合わせる。関係する決定があれば、全文を読んでから進める
- これから行う変更が決定に反するなら、進める前にユーザーに伝える
- 決定に反する変更をユーザーが承認したら、作業の終わりにその決定の置き換えを提案する。暫定の決定の論点が決着したときも、置き換えを提案する
- 決定の追加と置き換えは、ユーザーに頼まれたときだけ行う。直接編集せず、decision-record スキルを使う

@docs/decisions/index.md
```

## 守ること

- 既にある内容は書き換えない。`AGENTS.md` には末尾に足すだけにする
- 導入を頼まれたときは、確かめずに足してよい。決定を頼まれた流れで節を足すことになったときは、足す前にユーザーに確かめる
- 節の末尾にある `@docs/decisions/index.md` の行は、コードブロックやバッククォートで囲まずに書く。この1行が索引を毎セッション読み込ませる。囲むと読み込まれない
- ハーネスが `AGENTS.md` ではなく独自の指示ファイルを読む場合は、進める前にユーザーに伝える。その指示ファイルから `AGENTS.md` を読み込ませれば問題ない
- コミットはしない

## 確認

置いたあと、新しいセッションで「決定の索引には何が載っている？」と聞けば索引の内容が返る。この確認はユーザーに頼む。
