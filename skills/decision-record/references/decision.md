# 決定記録の作成と更新

プロジェクトにおいて「何を、なぜ決めたのか」を明確に残す決定記録です。複数の選択肢から1つを選定した経緯、修正せず受け入れると判断した制約、あえて行わないと合意した方針、論点が決着するまでの暫定的な取り決めなどを記録します。

## 記録を作成する

保存先は `docs/decisions/NNNN-<kebab-case>.md` です。
ファイル番号は `docs/decisions/` 内の最大番号に1を加え、4桁でゼロ埋め（ゼロパディング）します。最初の1件は `0001` です。

```markdown
---
description: "<どんな作業の前に参照すべきかを1文で簡潔に記述>"
status: accepted
date: <決定した日付 YYYY-MM-DD>
---

# <結論を明確に言い切る見出し>

## 背景

<なぜ決定が必要だったか。確認した事実には、いつどのような方法で確かめたかを明記する>

## 検討した選択肢

| 選択肢 | 評価 |
|---|---|
| <選択肢> | <選定した理由、または採用を見送った理由> |

## 決定事項

<具体的に何を決定したか>

## 影響

<この決定によって得られる利点、引き受けるトレードオフや不利益、今後の作業で遵守すべき事項>
```

- 見出しは「〜する」「〜しない」のように結論を言い切る表現にします。「〜について」のような曖昧な表現は避けます。索引にはこの見出しが掲載され、エージェントは見出しから結論を把握します
- 決定の理由や見送った代替案が会話や文脈から読み取れない場合は、推測で補填せずユーザーに確認します。理由が記録されていない決定事項は、後から変更してよいかの判断が困難になります
- 選択肢の比較を行わずに決定した場合は、「検討した選択肢」のセクションを省略します
- frontmatter は `description`、`status`、`date` の順に記載し、ステータスに応じて追加する項目（`tracking` など）はその後に配置します

### 暫定の決定記録

論点自体は未決着であるものの、結論が出るまでの間に適用する方針を定めた場合に作成します。上記の雛形を次のように変更します。

| 項目 | 記載方針 |
|---|---|
| `status` | `provisional` |
| `tracking` | frontmatter に追加。論点を管理している課題のURL。課題管理ツールを利用していない場合は省略 |
| 見出し | 「〜が決まるまで、〜する」のように、期限付きの暫定方針であることが分かる表現にする |
| 背景 | 結論を待っている論点を1文で明記する。`tracking` を省略した場合も、ここで論点が分かるようにする |
| 検討した選択肢 | 最終決定の候補として挙がっている案と、それぞれの懸念点 |
| 決定事項 | 結論が出るまでの暫定期間中に守るべき方針 |

論点そのものの議論過程や詳細な進捗は記録しません。それらは課題管理ツール側で管理します。

## 決定記録を置き換える

決定記録の本文は原則として書き換えません。いつ、何を決定したかという過去の経緯がそのまま残されていることに価値があるためです。
例外は置き換えに伴う frontmatter の更新のみであり、本文の記述内容は変更しません。

暫定の決定記録における論点が決着した際も、同様の手順で `accepted` の決定記録へ置き換えます。

1. 新しい決定記録を作成します。背景セクションに旧記録への相対リンクと、方針を変更する理由を明記します
2. 旧記録の frontmatter の `status` を `superseded` に変更し、`date` の後ろに `superseded_by: NNNN-xxx.md` を追加します。`description` は、経緯を確認したいときに参照するものだと分かる記述に修正します。本文は変更しません
3. 索引 `docs/decisions/index.md` から旧記録の行を削除し、新しい決定記録の行を追加します

ほかの決定記録から旧記録へ張られているリンクを張り替える必要はありません。決定記録の本文は書き換えないため、リンクは当時の経緯として残し、参照者は旧記録の `superseded_by` から新しい決定記録をたどります。

後継の方針を決めずに決定事項を廃止する場合も、同様の手順で新しい決定記録を作成し、廃止した事実とその理由を記録します。
