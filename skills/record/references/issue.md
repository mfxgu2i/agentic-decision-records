# issue

何が未解決なのかに答える記録。解決する意思のある問題と、まだ決まっていない論点を書く。
担当や期限を管理する作業チケットではない。索引に載せておくことで、エージェントが未決のことを決定済みとして扱うのを防ぐ。

## 書く

置き場所は `docs/records/issues/<kebab-case>.md`。

```markdown
---
type: issue
description: "<どんな作業の前に読むべきかを1文で>"
date: <最後に内容を直した日 YYYY-MM-DD>
---

# <何が未解決かを端的に示す一文>

<起きていること、または決まっていないこと>

## 分かっていること

<原因や調査の結果。いつ、何で確かめたか。確かめていない推測は推測と書く>

## 当面の扱い

<回避策。この問題に触れる作業での注意>
```

## 直す・閉じる

| 操作 | 手順 |
|---|---|
| 直す | 本文を直し、`date` を打ち直す。見出しや `description` が変わったら索引の行も同じ文に直す |
| 閉じる | 下の手順で片付ける |

片付いたissueは残さない。残すと、解決済みの問題を未解決として扱わせてしまうため。

1. 片付ける過程で決まったことがあれば、`references/adr.md` に従ってadrを書く。直して終わっただけなら何も書かない
2. issueのファイルを消し、索引から外す
3. 旧パスを検索し、ほかの記録からのリンクを修正する。リンク元の記述がissueを前提にしていれば、あわせて直す
