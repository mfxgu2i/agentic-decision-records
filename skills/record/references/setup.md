# 記録の仕組みを用意する

`docs/records/index.md` と、索引を毎セッション読み込ませる `AGENTS.md` の「プロジェクトの記録」の節を用意する。
記録の仕組みの導入を頼まれたとき、または記録を書く前の確認でどちらかが欠けていたときに行う。

## 用意するもの

| 前提 | 無いときに行うこと |
|---|---|
| `docs/records/index.md` | 下の「索引の雛形」で作る。`<プロジェクト名>` は、`AGENTS.md` やREADMEの見出しにあるプロジェクト名に置き換える。分からなければユーザーに聞く |
| `AGENTS.md` か `CLAUDE.md` のどこかにある `@docs/records/index.md` の行。位置や見出しは問わず、コードブロックやバッククォートで囲まれていないこと | 下の「節の原文」を、一字一句そのまま `AGENTS.md` の末尾に足す。コードブロックの囲みは含めない。`AGENTS.md` が無ければ、先頭にプロジェクト名の見出しと説明を1行書いて作る |

### 索引の雛形

```markdown
# <プロジェクト名> の記録

## ADR

## Runbook

## Issue
```

### 節の原文

```markdown
## プロジェクトの記録

`docs/records/index.md` の内容がコンテキストに無ければ、作業の最初に読む。

- ファイルや機能を変更する前に、その変更に関係する記録が索引にないか照らし合わせる。関係する記録があれば、全文を読んでから進める
- これから行う変更が記録に反する、または未解決の問題に関わるなら、進める前にユーザーに伝える
- 記録に反する変更をユーザーが承認したら、作業の終わりにその記録の置き換えを提案する。issueの問題を解決したときは、issueを閉じることを提案する
- 記録の追加、更新、削除は、ユーザーに頼まれたときだけ行う。直接編集せず、record スキルを使う

@docs/records/index.md
```

## 守ること

- 既にある内容は書き換えない。`AGENTS.md` には末尾に足すだけにする
- 導入を頼まれたときは、確かめずに足してよい。記録を頼まれた流れで節を足すことになったときは、足す前にユーザーに確かめる
- 節の末尾にある `@docs/records/index.md` の行は、コードブロックやバッククォートで囲まずに書く。この1行が索引を毎セッション読み込ませる。囲むと読み込まれない
- 作業ディレクトリかその上位に `CLAUDE.md`、`.claude/CLAUDE.md`、`CLAUDE.local.md` のいずれかがあると、Claude Codeは `AGENTS.md` を読まない。その場合は進める前にユーザーに伝える。`CLAUDE.md` に `@AGENTS.md` の1行があれば読まれるので、問題ない。ホームディレクトリの `~/.claude/CLAUDE.md` は関係しない
- コミットはしない

## 確認

置いたあと、新しいセッションで「記録の索引には何が載っている？」と聞けば索引の内容が返る。この確認はユーザーに頼む。
