# okf-query — Bundle検索手順

`knowledge/` を読み取り専用で検索し、作業判断に使える一次情報を出典付きで返す。
依頼元はこれから変更・調査・意思決定を行うエージェントで、裏取りと実作業は依頼元が行う。
バンドルの構造は `knowledge/AGENTS.md` が正本。必要になったらそちらを読む。

## バンドルルートの特定

カレントディレクトリに`index.md`と知識文書ディレクトリがあればそこ。なければGlobで
`**/knowledge/index.md`を探す。以降のGrepとGlobはこの配下に限定する。ワークスペースには
コードと`.claude/`があり、cacheのような一般語がそちらに大量ヒットするため。

## 検索手順

1. `index.md` の索引で候補の目星をつける。ワークスペースの`AGENTS.md`が`@knowledge/index.md`を
   インポートしているため既にコンテキストにあることが多く、その場合は取り直さない。
   タイトルか説明文が質問の主題を名指ししていれば手順3へ直行してよい。類推が要るなら手順2へ。
   直行先に必要な記述がなければ手順2に戻る。
2. 質問を意味分解し、複数の検索語で並列にGrepする。pathはバンドルルートに固定する:
   - 直接語。「問い合わせ」なら inquiry, contact, フォーム
   - 文書語への翻訳。「画像が出ない」なら image, uploads, cache, proxy
   - 周辺概念。「通知」なら notification, mail, webhook
   - frontmatter。`^type: Runbook` や `^tags:.*cache`

   打ち切ってよいのは、この3系統を試し、少なくとも1系統で英日・カタカナ・略語のゆれを変えて
   試した後。手がかりが無ければGlobで`**/*.md`を列挙し、索引に載っていない文書を確認する。
3. 該当文書だけをReadで熟読する。対象はgrepヒットのうち索引の説明文が主題に一致するもの。
   本文の絶対リンクや`resource:`が指す実体も必要範囲で辿る。

各論点について逐語抜粋と行範囲の出典が揃った時点で探索を止める。以降の裏取りは依頼元の仕事。

## 返却フォーマット

要約に丸めず、依頼元がそのまま作業判断に使える形で返す:

- 逐語抜粋。名称・数値・条件・手順は言い換えずに原文のまま引用する
- 行番号付き出典。ワークスペースルートからの相対パスで行範囲まで示す。
  `knowledge/specs/xxx-spec.md:24-31` のような形式。本文中の`/specs/...`はバンドルルート起点の
  表記なので、そのままの形では書かない
- 実体ポインタ。コードのパス・関数名、`_references/`の資産、外部URL。依頼元の裏取り先になる
- 落とし穴・既知リスク・未完箇所。独立した見出しで示す
- 鮮度。参照した文書のfrontmatter `timestamp`
- 要裏取りフラグ。記述時点の内容なので、依拠する前にコードや実体資産で確認すること

## 回答ルール

- 出典を示せない断定をしない
- 質問が複数の論点を含むなら、答えられた論点と答えられなかった論点を分けて返す
- 書いてあることと推測を区別する。補うときは「Bundleには記載がないが〜と考えられる」と明示する
- 複数文書で矛盾があれば両論を出典つきで併記する
- 探索過程は含めず、事実・出典・実体ポインタ・注意点に絞る
- 該当が無ければ「Bundleに該当する知識はない」と明言し、コード等の直接調査を提案する
- Bundleと一次情報の矛盾に気づいたら、一次情報を正として依頼元に報告する
