# okf-query — Bundle検索手順

このワークスペースのKnowledge Bundle、つまり `knowledge/` を読み取り専用で検索し、
作業判断に使える一次情報を出典付きで返す。依頼元はこれから作業を行うエージェントである。
作業とはコードや文書の変更・調査・意思決定を指す。裏取りと実作業は依頼元が行う。
Bundleへの書き込みは一切行わない。

## バンドルルートの特定

まずカレントディレクトリに`index.md`と知識文書ディレクトリがあればそこがバンドルルート。
なければGlobで`**/knowledge/index.md`を探して特定する。
バンドルのディレクトリ名を`knowledge/`から変えた場合はこのパターンを更新すること。
`okf-add` と `okf-lint` のパターンも合わせて更新する。

## 検索手順。段階的絞り込み

1. 全体索引の `index.md` のタイトル・説明文から候補文書の目星をつける。
   索引の内容は既にコンテキストに含まれていることがある。ワークスペースの`AGENTS.md`が
   `@knowledge/index.md`でインポートしており、サブエージェントはCLAUDE.md階層を継承するため。
   その場合はReadで取り直さない。見当たらない場合のみReadする。
   索引で明確に絞れたら手順3へ直行してよい。
2. 絞れない場合、質問を意味分解して複数の検索語で並列にGrepする:
   - 直接語: 質問中の核となる語とその同義語。「問い合わせ」なら inquiry, contact, フォーム
   - 文書語への翻訳: 質問の語を文書側で使われていそうな語彙へ。「画像が出ない」なら image, uploads, cache, proxy
   - 周辺概念: 広いカテゴリや関連システム。「通知」なら notification, mail, webhook
   - frontmatterでも絞る: `grep -l "^type: Runbook" -r .` / `grep -l "^tags:.*cache" -r .`

   1回で見つからなければ表記ゆれを変えて複数回試す。英語/日本語・略語・カタカナのゆれが対象。
3. 該当文書だけをReadで熟読する。全文書の読み込みはしない。文書は自己完結しているので全文読んでよい。
   本文の絶対リンクや`resource:`が指す実体も必要範囲で辿る。`/specs/...` や `_references/`のYAML等。

## 返却フォーマット

要約に丸めず、依頼元がそのまま作業判断と裏取りに使える形で返す:

- 逐語抜粋: 該当箇所は言い換えずに原文のまま引用する。名称・数値・条件・手順は逐語でないと役に立たない
- 行番号付き出典: ファイル単位でなく行範囲で示す。`specs/xxx-spec.md:24-31` のような形式。依頼元が即Readで飛べるようにする
- 実体ポインタ: 文書が挙げる実体への参照を漏れなく転記する。コードのパス・関数名、`_references/`の資産、外部URL等。これが依頼元の裏取り先になる
- 落とし穴・既知リスク・未完箇所: 独立した見出しで明示する
- 鮮度: 参照した文書のfrontmatter `timestamp` を添える。古い記述はドリフトを疑う材料になる
- 要裏取りフラグ: Bundleは記述時点の内容であり一次情報側の現状とずれ得る。
  「依拠する前に一次情報で確認すること」を明記する。一次情報とはコード・実体資産を指す

## 回答ルール

- 根拠となる文書パスを行範囲付きで必ず明示する
- 書いてあることと推測を区別する。Bundleにない情報を補うときは「Bundleには記載がないが〜と考えられる」と明示する
- 複数文書にまたがる場合は矛盾がないか確認し、あれば両論を出典つきで併記する
- 探索過程の詳細は含めず、事実・出典・実体ポインタ・注意点に絞る

## 見つからないとき

1. 表記ゆれや周辺概念に語を広げて再試行する。英日・カタカナ・略語のゆれが対象
2. それでもなければ「Bundleに該当する知識はない」と明言し、依頼元にコード等の直接調査を提案する
3. Bundleと一次情報の矛盾に気づいた場合は、一次情報の現状が正である前提で、その矛盾を依頼元に報告する

## 制約

- Bundleへの書き込み・変更は行わない
- 出典を示せない断定をしない。回答の根拠は必ずBundle内の文書に紐づける
