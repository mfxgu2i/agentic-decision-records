# okf-lint — バンドル健全性チェック

バンドル全体を OKF v0.1 の適合条件と、`okf-add` と本書が持つ執筆規約に照らして検査する。
機械的な不整合は修正し、内容に関わる問題は報告にとどめる。

判定基準は本書が持つ。バンドル側の `AGENTS.md` はバンドルを読むための構造説明であり、
規約の出典ではない。検査対象の運用ファイルでもない。

## バンドルルートの特定

まずカレントディレクトリに`index.md`と知識文書ディレクトリがあればそこがバンドルルート。
なければGlobで`**/knowledge/index.md`を探して特定する。
バンドルのディレクトリ名を`knowledge/`から変えた場合はこのパターンを更新すること。
`okf-query` と `okf-add` のパターンも合わせて更新する。

## 検査項目

### A. OKF 適合。違反は必ず修正

1. 予約ファイルの `index.md` / `log.md` 以外の全知識文書がパース可能な YAML frontmatter を持つ。
   `AGENTS.md` / `CLAUDE.md` は運用ファイルなので検査対象外。バンドルは`.claude/`を持たず、ツールはワークスペースルート側にある
2. すべての frontmatter に空でない `type` がある
3. 予約ファイルの構造:
   - ルート `index.md` の frontmatter は `okf_version` 宣言のみ。他の `index.md` に frontmatter がない
   - `index.md` のエントリが `* [タイトル](パス) - 説明` 形式
   - `log.md` の日付見出しが `## YYYY-MM-DD` 形式で新しい順

### B. 索引の整合。機械的に修正

4. 知識文書のうちルート `index.md` に載っていないもの。掲載漏れ
5. 索引エントリが指す先のファイルが存在しないもの。削除・改名の追従漏れ
6. 索引の説明文と frontmatter `description` の食い違い。frontmatter 側を正とする
7. `_references/index.md` について同上。また `_references/` 以外のディレクトリに
   `index.md` が存在しないこと。ルート索引と重複するため置かない運用

### C. 内容の健全性。報告のみで、修正はユーザーに確認

8. バンドル内リンクの切れ。OKF ではリンク切れは不正ではなく「未執筆の知識」の可能性が
   あるため、削除せず一覧で報告する。明らかなパスの誤記のみ修正してよい
9. `[[wikilink]]` や相対パスリンクの混入。バンドルルート絶対パスが推奨
10. 概念の重複、つまり同じ主題を扱う文書が複数ある状態。および `timestamp` が古いまま
    本文だけ更新されている疑いのある文書
11. `# Citations` の欠落。`type` では判定しない。type は自由定義のため。本文を読み、
    次のいずれかに由来する記述があるのに `# Citations` が無い文書を報告する:
    - 一次資料への言及。`_references/` 配下の資産、外部URL
    - 一次観測の記述。実機検証・ログ・DBクエリ結果・再現手順の結果
    - 断定的な原因説明や外部仕様の挙動に関する主張

    本文への追記は内容判断を伴うため自動修正せず、欠落文書を一覧で報告する
12. `# Citations` はあるが実質的な出典になっていないものを報告する。番号付きリストでない、
    一次資料/一次観測/意思決定の経緯のいずれも指していない、などが該当する。
    バンドル内で自己完結する文書に `# Citations` が無いのは違反ではない。報告しないこと
13. 収録方針、つまり `okf-add` の手順1から外れた文書を報告する。次の3類型:
    - コード事実の言い換えに留まり、意思決定・未解決課題・調査ログ等の要素が見当たらない
    - モデルが訓練データとして既に持っている一般知識の解説になっており、このプロジェクト固有の
      判断が無い。フレームワークの一般的なベストプラクティスなどが該当する
    - API・スキーマなど構造化できる仕様を散文で写している。`_references/`に実体を置き、
      文書は`resource:`で指すポインタと、判断・落とし穴に絞るべきケース

    いずれも判断が難しい場合や、本文が短く自己完結する文書は無理に報告しない。用語定義などが該当する
14. `# Citations` にコード、つまりファイルパスや関数名が出典として挙がっている文書を報告する。
    コードを出典にするのはアンチパターンで、その主張がコードから再現できる内容である
    シグナル。`okf-add` の「Citations」節を参照。本文の書き直しを伴うため
    自動修正はせず報告のみ。本文中のナビゲーション目的のポインタは対象外

## 手順

1. 全 .md ファイルを列挙し、A → B → C の順に検査する
2. A・B の違反は修正する。C は報告のみ
3. 結果をユーザーに報告する。検査ファイル数・違反ゼロの項目・修正した項目・報告事項を伝える
4. `log.md` に1行追記する:

```
* Update: lint 実行。<N> ファイル検査、修正 <M> 件。概要を添える。報告 <K> 件。
```

修正ゼロでも実行記録は残す。既存行は変更しない。
