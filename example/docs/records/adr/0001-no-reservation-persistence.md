# 予約データを永続化せず、メール通知だけにする

## 背景

席予約フォームを作るにあたり、受け付けた予約をどこに保存するか決める必要があった。
店舗は開業時から紙の台帳で予約を管理しており、電話で受けた予約もそこに書き込んでいる。

| 検討した選択肢 | 評価 |
|---|---|
| DBに保存し、管理画面を作る | 台帳が二重になり、電話予約との突き合わせが毎日発生する。DBと管理画面の保守も増える |
| メール通知だけにする | スタッフがメールを見て台帳に転記する手間は残るが、正となる台帳がひとつで済む |

## 決定

予約はNext.jsのAPI Routeからメールを送るだけにし、DBには保存しない。予約情報の正式な記録先は店舗の台帳とする。

## 影響

- 予約の一覧、変更、キャンセルの機能はサイト側に作れない。変更とキャンセルは電話で受ける
- 空席の自動判定ができない。満席のときは店舗から折り返し連絡する
- メール送信の失敗がそのまま予約の取りこぼしになる。送信処理のエラーは握りつぶさない
