# 画像差し替えの反映が手動のキャッシュパージに頼っている

メニュー画像を同じファイル名で差し替えると、CDNのキャッシュを手動でパージするまで古い画像が表示され続ける。
パージを忘れると、古い画像が最大1日ほど残る。恒久的な対処方法は決まっていない。

## 分かっていること

画像はCDN経由で配信しており、URLの変換は `getMenuImageUrl()` が行う。
ファイル名が同じならURLが変わらないので、CDNのキャッシュがヒットし続ける。
CDN経由にした経緯は [CDN経由で配信する決定](../adr/0003-route-menu-images-through-cdn.md) にある。

| 主張 | 確かめ方 |
|---|---|
| 差し替え後もキャッシュがヒットし続ける | 2026-07-24の実機検証で、差し替え後もレスポンスヘッダーの `x-cache: HIT` が続くことを観測した |
| キャッシュは約24時間残る | 推測。CDNのTTLは既定値のままで、既定値は公式仕様で確かめていない |

恒久的な対処方法として、次の2案が挙がっている。

| 候補 | 懸念 |
|---|---|
| 画像URLにコンテンツハッシュを付ける | `getMenuImageUrl()` の変換規則が変わる。CMSからハッシュを得る方法を確かめていない |
| CMSの更新Webhookからパージを自動で呼ぶ | Webhookの受け口を新しく運用することになる |

## 当面の扱い

- 差し替えのたびに手動でパージする。[季節メニュー入れ替えの手順](../runbooks/seasonal-menu-update.md) の手順3に含まれている
- 「画像が更新されない」という問い合わせは、まずパージの実行漏れを疑う
- `getMenuImageUrl()` を変更するときは、方式が決まるまでURLの形式を変えない
