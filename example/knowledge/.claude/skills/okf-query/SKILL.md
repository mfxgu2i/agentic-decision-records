# okf-query — 知識の取り出しワークフロー

バンドルに蓄積された知識から質問に回答する。**段階的絞り込み**(索引→検索→熟読)で
無関係な文書をコンテキストに載せず、**出典を明示**して答える。このスキルは読み取り専用
であり、バンドルへの書き込みは一切行わない。

## 手順

### 1. 索引で当たりをつける(progressive disclosure)

ルート`index.md`を読み、タイトル・説明文から候補文書を特定する。
セクションは文書のトピック分類を表している。
ここで候補が明確に絞れたら手順3へ直行してよい。

### 2. 検索バリエーションで網を張る

索引だけで絞れない場合、質問を意味分解して**複数の検索語で並列にGrep**する:

- **バリエーション1(直接語)**: 質問中の核となる語とその同義語
  (例: 「問い合わせ」→ inquiry, contact, フォーム)
- **バリエーション2(文書語への翻訳)**: 質問の語を文書側で使われていそうな語彙に変換
  (例: 「画像が出ない」→ image, uploads, cache, proxy)
- **バリエーション3(周辺概念)**: より広いカテゴリや関連システム
  (例: 「通知」→ notification, mail, webhook)

frontmatterによる絞り込みも活用する:

```
grep -l "^type: Investigation" -r .   # 種別で絞る
grep -l "^tags:.*cache" -r .          # タグで絞る
```

同じ意味の検索を重複して打たない。ヒットがなければ語を変えて再試行する。

### 3. 該当文書だけ読む

絞り込んだ文書をReadする。文書は自己完結しているので全文を読んでよい。
本文中のバンドル絶対リンク(`/specs/...` 等)が指す関連文書、およびfrontmatterの
`resource:`が指す実体ファイル(`_references/`のYAML等)も、回答に必要な範囲で辿る。

### 4. 回答を組み立てる

- **出典を明示する**: どの文書に基づくかをパスで示す(例: `specs/xxx-spec.md`)
- **書いてあることと推測を区別する**: バンドルにない情報を補う場合は
  「バンドルには記載がないが〜と考えられる」と明示する
- 複数文書にまたがる場合は矛盾がないか確認し、あれば両論を出典つきで併記する

### 5. 見つからないとき

1. 表記ゆれ(英日・カタカナ・略語)や周辺概念に語を広げて再試行する
2. それでもなければ**「バンドルに該当する知識はない」と明言**し、
   コードの直接調査を提案する
3. 調査の結果、バンドルに残す価値のある知見が得られたら、`okf-add`での追加を提案する
   (このスキル自身は書き込まない)

## 制約

- バンドルへの書き込み・変更は行わない
- 回答の根拠は必ずバンドル内の文書に紐づける。出典を示せない断定をしない
